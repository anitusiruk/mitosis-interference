# Administrative execution amendment for static-baseline tuning

At 2026-10-07 01:34 UTC, before any Day-17 replay or tuning outcome, the live
diagnostic queue had completed all 20 BERT trajectories and four Day-15 observer
trajectories. All four observers passed their exact reference replay. The
remaining all-mature-batch factorial audits would consume most of the remaining
evening. The previously staged sequential static queue would therefore risk
never starting before the administrative cutoff.

Run the unchanged Day-17 rank/rate protocol in a separate Git worktree, on branch
`day17-static-tuning-20261006` of the same `anitusiruk/mitosis-interference`
repository. This is execution isolation, not a new repository, dataset,
hyperparameter grid, selection metric, or scientific comparison. Preserve all
24 pilots, the pilot-only rate-selection receipt before confirmation, and all
20 planned paired development confirmations. Do not select or reduce coverage
according to outcomes. Keep the original replay gate, stream hashes, clipping,
initialization, memory budget and training recipe unchanged.

Both queues share one RTX 4090. A complete bitwise static replay must pass under
this execution environment before the first pilot is launched. A failure halts
the static queue and preserves the attempted replay. Neither training-time
comparisons nor GPU utilization during overlapping work are dedicated compute
benchmarks. Timing and peak-memory receipts are descriptive. A passing replay
checks this concrete implementation; it is not a proof about all GPU scheduling.

Use separate worktree indexes, output folders and execution locks. The original
worker continues its unchanged queue and original cutoff. The static worker
commits each attempt to its branch, verifies the remote ref, and independently
downloads and hashes every newly generated Day-17 LFS checkpoint. It never
rewrites the main checkout's preservation manifest or existing backup receipts.
Unrelated old checkpoint files remain Git LFS pointers in the auxiliary worktree;
the exact rank-96 replay reference is materialized from already verified objects.

After both queues finish and both remote checkpoint receipts pass, merge the
static branch into `day5-causal-audit` without overwriting independent results.
Refresh the manuscript with actual coverage, including any administrative partial
Day-15 coverage. Recompute the complete checkpoint manifest and verify the final
combined GitHub snapshot. Failed attempts remain part of the record. The
10:00 PM Dallas launch cutoff, 10:15 PM training deadline and 10:25 PM integration
target remain administrative limits. If integration cannot finish, leave both
branches preserved and report the exact remaining step.

This amendment changes execution scheduling only. The adaptive references and
development examples had already been examined before the static study; its
results do not become untouched final evaluation through this isolation.
