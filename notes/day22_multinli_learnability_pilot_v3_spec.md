# Longer-context single-learner learnability pilot

Development pilot declared before its new outcomes. It does not replace or hide the previous 64-token, 1440-example stress study. The goal is to establish that a natural same-label stream can be learned before using it for allocation attribution. Passing this gate does not establish novelty, competitive performance or a continual-learning benefit.

Use only the pinned `nyu-mll/multi_nli` training split. Genres are fiction (A), government (B), telephone (C), with all three entailment labels. Reuse the normalized-premise SHA-256 modulo-10 development partition and the fixed seed-424242 64-examples-per-label-per-genre selection rule. This partition has been viewed in earlier stress experiments and is not untouched confirmation; duplicate removal can change individual selected rows. Remove duplicate normalized premise/hypothesis pairs deterministically, preserving the first row for unambiguous pairs and recording counts; remove every row of a normalized pair whose labels conflict, recording all excluded pair hashes, labels and source IDs before any sampling. All hypotheses sharing a premise stay in the same fit/development partition.

Pilot seed 2026 selects 384 examples per class per occurrence: 1152 per segment and 5760 unique training pairs across A1 B1 A2 C1 B2. The B-first order uses B1 A1 B2 C1 A2 and exactly the same data batches. Each example receives one incoming update; batch size 16 gives 360 updates. Use explicit text/text_pair tokenization, longest-first truncation at 256 tokens, and record untruncated lengths, truncation fractions at 64/128/256 and train/development group overlap. Preserve the prepared data and its source IDs, group keys, labels and hashes. No official matched/mismatched validation or test split is loaded.

Use the original pinned DistilBERT backbone/tokenizer, rank-8 LoRA on q_lin/v_lin, alpha 16, LoRA dropout zero, the model's original classifier-stack dropout, and the existing full classifier-stack training recipe. One fixed private package receives every update; no allocation, protected-memory filtering or rehearsal update is used. Keep AdamW betas (0.9, 0.999), epsilon 1e-8, weight decay 0.01, gradient norm clipping at 1.0, full precision and no scheduler. The three equally budgeted rates are 5e-5, 2e-4 and 8e-4, each in both orders. Retain every candidate and attempt. Evaluation occurs at initialization and all five segment ends; report three-class accuracy and loss per genre and per class, and preserve per-example logits. Evaluation restores RNG and model modes. Store final adapters, heads, optimizer state and RNG for every completed or deadline-stopped attempt.

Before full pilots, time a separate 32-update canonical prefix at 2e-4, including initial and prefix-end evaluations. This prefix is used only for time/memory admission; its learning outcomes cannot change the grid, threshold, data or protocol. Let the projected full cost be 1.5 times (360/32 times prefix training seconds + three times total two-evaluation seconds + measured startup/checkpoint cost). Admit pilots only if this is below 600 seconds and peak allocated GPU memory is below 4 GiB. Every individual GPU process has a 23-minute internal deadline and 25-minute external process-group cap. Require an idle GPU and the same single-worker lock. Launch one job manually; no automatic grid or confirmation queue.

After all six candidates complete, select the rate with highest mean final genre-macro accuracy across both orders; exact ties within 1e-12 favor the smaller rate. A rate passes the operational learnability gate only if its order-averaged final macro accuracy is at least 0.50, its improvement over the order-averaged untrained macro accuracy is at least 0.10, and every order-averaged genre accuracy is at least 0.40. These thresholds are fixed before outcomes, are not statistical significance tests, and do not license selecting genres or orders. If no rate passes, report the failure without expanding this grid or running a favorable confirmation. If a rate passes, freeze a separate fresh-seed comparison specification before any adaptive comparison; do not automatically launch it.

The pilot is method development using one previously used seed and repeatedly viewed development examples. It is not a final held-out evaluation. Later confirmation requires fresh training seeds, paired orders, matched allocation controls, explicit resource budgets and a separately frozen evaluation protocol. Save artifacts only in the existing `mitosis-interference` repository.
