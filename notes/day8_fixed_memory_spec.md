# Fixed-total-reservoir sensitivity, declared before its outcomes

The original reference allocates 512 stored training items **per adapter**, so growing pools have more memory than a single learner. Add a separate, labeled extension with a fixed total budget of 512 items across the pool. At K adapters, each reservoir receives floor(512/K) slots. On real spawn, uniformly subsample old reservoirs using their private reservoir RNG, preserve each reservoir's full historical seen count, set capacities to the new quota, and allocate the new reservoir its quota before its first real update. Standard reservoir replacement with the preserved seen count continues. This subsampling preserves uniformity over the historical stream conditional on the existing uniform sample.

Set the hard maximum at eight adapters so every quota remains at least the unchanged 64-item probe requirement. At that cap, disable fresh eligibility and retain the frozen ordinary-reuse/full-batch-guard fallback. Log cap rejections; do not silently change the harm threshold, warmup threshold, optimizer or confirmation rule. This is a memory-budgeted extension of CAU-v1, not a claim that its trajectory should reproduce the original per-adapter protocol. It controls reservoir storage, **not** total classifier/LoRA capacity or inference compute.

Run private-package and zero-LoRA head-only CAU on BANKING and Amazon: development pilot seed 2026/canonical; seeds 2027–2031 with both canonical and B-first orders. Forty-four trajectories, compared to the exactly corresponding completed per-adapter reference inputs. All three original fixed inference rules remain reported; an auxiliary learned gate may be applied afterward using the same already frozen training-only routing procedure. No official-test evaluation, outcome-selected thresholds or routing-rule selection.

Verify the hard storage bound after every real update, preserve old historical seen counts across shrink, check mature probe eligibility, and require exact shadow state restoration under a real tiny PEFT model before live runs. Store total allocated slots, actual replay items, all classifier/LoRA parameters, optimizer bytes, learning updates and elapsed time separately. The budget is not a rehearsal-training budget: reservoirs still protect/route only, and real training sees only incoming batches.

The budgeted extension also restores stale gradients, per-parameter trainability flags and individual module modes around legacy probes. Original private-package probes clear stale gradients, which the next real update already clears before backward; that behavior is preserved in the frozen reference rather than silently patched mid-batch. The extension's cleanup must pass stricter full-state snapshots and a no-shrink numerical equivalence check. No original learner files are modified while their queues run.

Seed/order is the statistical unit. Compare budget effects within each seed/order/architecture/regime/rule; average the two orders inside each seed before a descriptive Student-t interval over five independent seed clusters. Keep seed 2026 separate. This experiment is a predeclared sensitivity extension motivated by a known fairness limitation, not an untouched confirmatory evaluation of the complete eventual submission method. It follows all existing GPU queues and retains the 03:20 launch and 03:25 checkpoint cutoff on 2026-10-06.
