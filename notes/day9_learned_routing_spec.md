# Auxiliary learned routing diagnostic, declared before its outcomes

Day-5 nearest-centroid inference does not recover oracle specialist performance. Evaluate two standard learned routing rules after the frozen learners finish. This changes neither training decisions nor classifier weights and is not claimed as novel: memory-trained adapter routers already exist, including L2R (https://aclanthology.org/2024.findings-emnlp.38/) and density-guided retrieval in HESTIA (https://proceedings.mlr.press/v337/le26a.html).

For each final checkpoint, encode the stored training texts in its reservoirs using the unchanged frozen DistilBERT mean-pooled normalized features. Ignore gold class labels and true concept/genre metadata during router fitting. The router target is the adapter that owns each stored example, determined by the learner's past training assignment. Thus early misassignments remain in the router training set; no oracle corrections.

Fit StandardScaler and multinomial LogisticRegression (C=1, solver=lbfgs, max_iter=1000, tol=1e-6) on these training features only. A one-adapter pool needs no fitted gate. Rules: (1) linear_hard, select the classifier with largest routing probability; (2) linear_probability_mixture, weight each classifier's full-label-space softmax probabilities by the router probabilities. No label masking, calibration, threshold selection, cross-validation or development-set model selection. Report both alongside all original fixed routers.

Reload each learner and require exact agreement in original final development accuracies and evaluation counts with the stored last-active, uniform-probability and centroid tables before accepting auxiliary scores. A mismatch stops evaluation for inspection rather than silently accepting a different model. Keep router parameters, fitting seconds and inference seconds separate from learner resources. Save fitted router coefficients and training-only normalization statistics, plus source/checkpoint provenance.

Apply to completed private/head-only Day-5, Day-6 and MultiNLI runs, following the main GPU queues. Fit and predict without using development labels; access labels only for the final metric calculation. Official test/validation constraints remain those of each frozen regime. This is an auxiliary development diagnostic introduced after observing seed 2026's routing weakness. Do not present it as a prespecified primary outcome of the earlier seed batch, an untouched final-test result, or a reproduction of L2R/HESTIA. New routing rules require later confirmation after the complete method is frozen.
